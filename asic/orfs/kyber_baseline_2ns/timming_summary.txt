This run is the Kyber fixed-setting baseline.

The 80% core-utilization / 0.80 placement-density setting was
selected previously from the Dilithium 500 MHz PPA exploration
as the highest-density timing-clean / high-density best-PPA
candidate. Kyber was not independently density-optimized.

The physical setting is intentionally held fixed to evaluate
compile-time portability, implementation cost, and frequency
headroom of the Kyber variant under the previously selected
implementation recipe.

Frequency Characterization
--------------------------
The same 80% core-utilization / 0.80 placement-density setting
was retained while only the clock constraint was changed.

2.00 ns / 500.00 MHz    : PASS, setup WNS +0.111675 ns
1.80 ns / 555.56 MHz    : PASS, setup WNS +0.043978 ns
1.75 ns / 571.43 MHz    : PASS, setup WNS +0.0225774 ns
1.70 ns / 588.24 MHz    : FAIL, setup WNS -0.00415645 ns

At the selected 0.05 ns sweep resolution, the maximum
timing-clean frequency observed under this fixed physical
setting is 571.43 MHz at 1.75 ns.

The nearest tested higher-frequency point is 588.24 MHz at
1.70 ns, which is DRC-clean and antenna-clean but fails setup
timing by approximately 4.16 ps.


Interpretation
--------------
The Kyber variant closes setup and hold timing at the fixed
500 MHz baseline with zero detailed-route and antenna violations.

The narrower 12-bit Kyber datapath and reduced internal storage
produce substantially lower mapped and physical implementation
cost than the 23-bit Dilithium variant when both are evaluated
at the same 2.0 ns / 500 MHz, 80% core-utilization, and 0.80
placement-density setting.

The 571.43 MHz result is an implementation-flow characterization
under the inherited high-density setting. It is not a measured
silicon Fmax and should not be treated as a controlled direct
Fmax comparison with the published Dilithium clock sweep, which
used a 30% core-utilization / 0.60 placement-density condition.
